# TEAM 01 개발자 → 검증 담당자 인수인계서

> 목적: 제작 담당자가 변경한 코드의 범위·설계 의도·알려진 제약을 전달합니다. **이 문서는 검증 결과가 아니며**, 검증 담당자가 별도 채팅/환경에서 실험한 결과만 PASS로 인정합니다.
>
> 대상: \`nahee2345/urrc_2_f1\` / \`src/team_01/team01_race\`
>
> 역할: **제작 담당자**는 구현·수정·GitHub 반영·변경 내역 작성, **검증 담당자**는 실행·계측·원인 분류·증거 수집·보고만 담당합니다. 검증 담당자가 직접 코드를 바꾼 경우 반드시 별도 커밋으로 명시합니다.

## 1. 목표와 범위

- 목표: 사전 트랙 경로를 모르는 F1 계열 트랙을 센서로 탐색하고, 1랩의 SLAM 경로·도로 경계를 학습한 뒤 2랩부터 지도 기반 경로를 참고합니다.
- 단계별 목표: 첫 랩 명령속도 상한 5 m/s; **검증된 지도 목표점이 있을 때** 상한 10 m/s. 이는 **상한 설정**이지 실제 10 m/s 달성·완주 보증이 아닙니다.
- 차량: Gazebo Harmonic, ROS 2 Jazzy, RGB 카메라, Depth 카메라, 전·후방 2D LiDAR, 차량 Odometry. 현재 차량 모델에 3D LiDAR는 연결되어 있지 않습니다.
- 우선순위: 무충돌·무이탈·신호준수 > 유효 경로 유지 > 조향 진동 감소 > 우회·재합류 > 목표 속도.
- '어떤 트랙이 와도 주행 가능'은 개발 목표입니다. 인식거리·도로 유형·가파른 코너·계측 지연·SLAM 실패 등 일반화 한계는 별도로 검증해야 합니다.

## 3. 이전 구조에서 무엇을 수정했는가

1. 700줄 이상으로 결합되어 있던 \`planning.py\` 기능을 \`planning_gate.py\`, \`planning_road.py\`, \`planning_geometry.py\`, \`planning.py\`로 분리했습니다.
2. \`node.py\`의 기본 파라미터·진단 기록을 \`defaults.py\`, \`node_diagnostics.py\`로 분리했습니다. **수정된 Python 파일은 각 400줄 미만으로 설계**했습니다.
3. 코너 진입→Apex→탈출마다 강제로 측면 오프셋을 바꾸던 Out-In-Out 동작을 제거하여, 기존의 안전한 경로를 유지하도록 했습니다.
4. 선택한 조향 명령에 **조향 변화율과 조향가속도 제한**을 적용했습니다. 이는 S자 진동 완화 목적이며 실제 개선 여부는 별도 검증해야 합니다.
5. 우회 후 기존 경로에 복귀하도록 상태기계 및 5차 보간 오프셋을 도입했습니다. 장애물이 화면에서 사라진다고 즉시 0m 오프셋으로 점프하지 않도록 했습니다.
6. SLAM 좌표 기반 1랩 중심선 샘플과 지도 유효성 게이트를 추가했습니다. 검증 전 2랩 지도 사용·추월 사용은 차단될 수 있습니다.
7. 현재 실시간 인식된 도로 범위와 제동거리/곡률을 이용해 속도 목표를 제한했습니다. **1랩 5m/s, 지도 유효 시 2랩 최대 10m/s** 상한이 적용됩니다.
8. 기존 신호등 출발과 차량 모델 연결은 유지했습니다. 학습된 지도는 다음 경주에서 무조건 자동 재사용하지 않습니다.

## 4. 구현하지 않았거나 여전히 약한 부분

- RTAB-Map의 **실제 Loop Closure 백엔드 품질**, 잘못된 루프 폐합 방지, 모든 트랙에서의 좌표 정확도는 입증되지 않았습니다. \`SLAM_MAP_PROVISIONAL_CLOSED\`는 기하학적 후보일 뿐입니다.
- 첫 랩 샘플은 **단순 평활 중심선**이며 Minimum-Curvature / Minimum-Time 전역 최적화는 아직 구현되지 않았습니다.
- \`rejoin.py\`는 5차 횡방향 보간을 사용하지만 **완전한 Frenet Lattice**, 미래 시간별 다중차량 예측, 최적 ST 궤적 충돌검사는 구현되지 않았습니다.
- 경로 제어는 국소 후보 + Pure Pursuit 계열이며 **LQR·MPC·MPPI/MPCC 본격 제어 구현과 성능 비교는 차기 개발 대상**입니다.
- 상대 차량은 단순 깊이 반환점 기반 추정에 가까우며, DBSCAN 다중 객체 ID 추적·IMM/CTRV 예측이 완성된 상태는 아닙니다.
- \`mapping_lap_speed_mps\`, \`mapped_lap_speed_mps\` 등 설정이 **실제 속도 제한에 직접 연결된 경로인지** 확인이 필요합니다. 현재 \`planning.py\`에는 별도 5/10m/s 상한이 존재합니다.
- 미확인 지역은 통과 가능으로 가정하면 안 됩니다. **고속에서 2D LiDAR 최대거리·Depth 거리·센서 지연**이 성능 상한을 결정합니다.
- 리어 센서 상실, 지도 품질 저하, 좁은 코너, 추월 중 센서 상실 후 재합류는 고위험 경계 사례입니다.
- 기존 단위 테스트 일부는 **이전 알고리즘의 요구사항**을 검사했으므로, 테스트의 설계 목적과 현재 구현 의도를 구별해야 합니다.
- ROS 2/Gazebo 실제 완주, 전 트랙 일반화, 10m/s 안정화는 **미검증**입니다.

## 5. 검증 담당자가 매 실행에서 우선 확인할 사항

**공통 P0 (어느 단계든 반드시 확인)**

- 실행 커밋 SHA, OS/ROS/Gazebo/패키지 버전, 실행 명령, 실제 트랙·차량 스폰 위치·시작 시간을 기록합니다.
- 카메라 신호등 소등 전 출발 여부, 출발 이후 각 센서 토픽 주기와 정상값, 통신/TF 타임스탬프를 확인합니다.
- 시작부터 종료까지 **실제 주행 거리, 완주 랩 수, 최댓속도, 도로 이탈, 차체 충돌, 정지 원인**을 확보합니다.
- 제어 명령과 실제 움직임을 분리 측정합니다. \`speed command=10\`은 \`actual speed=10\`의 증거가 아닙니다.
- 로그가 없거나 영상만 있다면 판정은 **UNVERIFIED**로 두고, 단순 출발·컴파일 성공을 완주 PASS로 보고하지 않습니다.

**단계별 중점**

| 우선 | 시험 | 반드시 관찰할 항목 | 통과 기준 제안 (검증 담당자가 확정) |
|---|---|---|---|
| 1 | Build + 단위 테스트 | import, launch, 누락 의존성, 회귀 테스트 | 빌드·해당 테스트 완료, 예외 없음 |
| 2 | 신호 출발 | 4→0/5→0 시퀀스, 단발 플래시, 출발 승인 | 소등 전 0m 이동·조건 만족 시 출발 |
| 3 | 1랩 3~5m/s | 곡률 예측, 좌우 경계, S자 조향, 조기 감속 | 충돌·이탈 없이 주행, 제어 진동 근거 기록 |
| 4 | RTAB-Map | RGB-D/scan 입력·TF map→odom→base_link·Loop Closure | 실제 SLAM 그래프와 지도 폐합 모두 확인 |
| 5 | 2랩 전환 | 지도 저장 여부, 목표점 위치, 지도/실도로 일치 | 유효 지도만 사용, 불일치 시 안전 감속 |
| 6 | 5→8→10m/s | 실제 속도, 횡오차, yaw 진동, 제동거리 | 반복 실주행 완주·계측 기준 충족 |
| 7 | 정적 장애물 우회 | 좌/우 선택, 측면 간격, 재합류 시작과 종료 | 충돌 없이 SHIFT→PASS→MERGE→CRUISE |
| 8 | 저속 상대차 추월 | 상대속도 추정, 앞/뒤 간격, 차선 유지 | 실제 앞차 추월 및 안전한 원래 경로 복귀 |
| 9 | 복잡한 트랙 | Monaco/Spa/Baku/COTA 등 다른 곡률·고저차 | 트랙별 결과 별도 기록, 하나의 PASS로 일반화 금지 |
| 10 | 실패·복구 | RGB/Depth/LiDAR/TF 누락·지연·상충 | 무리한 가속/급조향 없이 감속·정지 또는 안전 복구 |

위 수치는 실험 계획이며 **실행해서 통과했다는 뜻이 아닙니다**.

## 6. 실패 원인 분류 규칙

- \`BUILD_DEPENDENCY\`: 설치·import·빌드·런치/토픽 브리지 연결 오류
- \`SIGNAL_GATE\`: 4→0 / 5→0 인식 오류, 조기 출발/출발 불가
- \`PERCEPTION\`: 도로/연석/경사/상대차/장애물 오분류
- \`SYNC_TF\`: 메시지 시각 차이, 맵 프레임 누락, TF 오래됨·점프
- \`SLAM_LOOP\`: 샘플 부족·루프 폐합 실패·위치 드리프트
- \`ROUTE_PLANNING\`: 잘못된 경로·다중 경로 선택 진동·재합류 실패
- \`STEERING_CONTROL\`: 조향 지연·속도 대비 과조향·S자 진동
- \`VELOCITY_BRAKING\`: 실제속도 부족/초과·제동거리 부족·불필요한 급정지
- \`COLLISION_OFFTRACK\`: 실제 충돌·경계 이탈
- \`UNKNOWN\`: 충분한 로그가 없어 원인을 판정할 수 없음

최초 이상이 발생한 시점부터 **원인→근거→재현→예상 동작→실제 동작** 순서로 보고합니다. 여러 원인이 의심되면 확정/가설을 구분합니다.

## 7. 검증 결과에서 제작 담당자에게 반드시 전달할 값

1. 커밋 SHA 및 검증 변경 여부(원본 그대로 실행했는지).
2. 실제 트랙·경주 규칙·속도 목표·차량 수·장애물 배치.
3. 단계별 PASS / FAIL / UNVERIFIED / BLOCKED 및 첫 실패 단계.
4. 출발까지 소요시간, 실주행 거리/랩 수, 목표·실측 최고속도, 충돌/이탈.
5. S자 구간: 위치/시간, **명령 조향각·실제 yaw rate·횡오차**, 진동 주기/최대 진폭.
6. 지도 구간: TF 유효성·나이, 샘플 수, Loop Closure 관측, 2랩 지도 전환 여부.
7. 추월 구간: CRUISE/SHIFT/PASS/MERGE/HOLD 진입·탈출 시각, 대상차 속도, 최소 간격, 복귀 완료 여부.
8. 검증 로그와 rosbag/영상/지도 파일 링크, 재현 명령, 관련 소스/함수.
9. 검증 담당자의 **최소 수정 요청**(무엇을 고쳐야 하는지)과 근거. 검증 결과 없는 임의 파라미터 제안은 가설로 표기합니다.
10. 수정 후 다시 확인해야 할 회귀 항목과 이전 커밋 대비 성능 차이.

## 8. 제작 담당자 수정 원칙 (후속 커밋 공통)

- 하나의 Python 소스 파일은 **400줄 미만**을 유지하고, 인식/지도/경로/제어/안전을 기능별 파일로 분리합니다.
- 실패 원인이 확인되기 전 여러 모듈을 동시에 광범위하게 변경하지 않습니다. 원인별 단위로 수정하고 커밋을 구분합니다.
- 위험한 임시 우회(신호 미확인 출발, 센서 실패 시 강제 가속, 도로 경계 무시, 무조건 트랙 XY 사용)는 추가하지 않습니다.
- 여러 알고리즘이 동시 조향 명령을 발행하지 않도록 **단일 최종 제어 경로**를 유지합니다.
- 속도 상승보다 먼저 제어 명령·실제 차량 응답·안전 경로의 일치 여부를 확인할 수 있도록 진단 정보를 확보합니다.
- 변경 시 **변경 전 증상 → 원인/가설 → 수정 파일·함수 → 안전 영향 → 다음 검증 기준** 5개를 남깁니다.
- 별도 검증 담당자가 보고서를 보내면 제작 담당자는 코드 수정·GitHub push·다음 인수인계 갱신을 수행합니다.
