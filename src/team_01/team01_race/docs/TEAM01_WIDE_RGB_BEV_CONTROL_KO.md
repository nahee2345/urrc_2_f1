# TEAM 01 넓은 RGB / BEV / 중앙 경로 제어: 개발·검증 안내

## 센서와 트랙 (트랙 submodule 기준)
- road_rgb 수평 화각을 약 92°에서 105°로 확대했습니다.
- Depth 수평 화각은 92°로 유지했습니다. road_rgb와 Depth는 동일한 장착 좌표를 사용하며 픽셀은 pinhole 모델로 재투영합니다.
- front_rgb 신호등 카메라 및 신호 판정 규칙은 변경하지 않았습니다.
- 도로 아스팔트 기본 텍스처 RGB=(42,44,47), 바깥 RGB=(73,79,68), 빨간/흰색 경계벽 높이 약 0.8m.
- 위 색상은 텍스처 설정값이며 물리 Gazebo 조명과 노출에서 실제 픽셀값은 달라질 수 있습니다.

## 데이터 처리 원칙
1. Depth의 지면 평면에서 RGB 아스팔트 픽셀을 확인해 도로 윤곽을 생성합니다.
2. 빨간/흰색 벽 색상은 Depth에서 높이 8.5~65cm인 장애물 픽셀과 일치해야 후보가 됩니다.
3. 후보점은 전방 LiDAR 거리와 25cm 이내로 일치하는 경우에만 경계벽 교차 검증 수에 포함합니다.
4. RGB-Depth 도로와 양측 LiDAR 연석이 충분히 일치하면 검증된 융합 경계를 이용합니다.
5. 센서가 불일치하면 이전 도로를 ego-motion으로 보정해 어떤 현재 측정이 안정적인지 결정합니다.
6. 과거 프레임만으로 자유공간을 생성하지 않습니다. 현재 유효한 경계가 없으면 도로 추종을 중단합니다.
7. near(0.5~3m), middle(3~6m), far(6~10m) ROI를 수치로 구분합니다. 관측되지 않은 먼 구간은 invalid입니다.
8. Stanley 조향에서는 작은 직선 오차에 대한 데드밴드를 적용하고, 코너에서는 실제 거리 간격을 반영한 곡률 feedforward를 적용합니다.

## 실시간 시각화/기록
- `/team01/debug/bev` : 10Hz nav_msgs/OccupancyGrid. base_link 기준, 0.2m 셀, 10m 전방, 좌우 ±3m; -1 미확인/0 검증도로/100 장애물.
- `/team01/debug/path` : 20Hz JSON. `road_roi`, `road_source`, `reference_xy`, `reference_valid`, `planner`, `cmd_steer`, `reason`.
- `~/.local/state/urrc_team01/road/latest.png` : 실제 도로 RGB 위에 노란색 인식경계, 초록색 중심, 자홍색 계획경로.
- GUI RViz에서 OccupancyGrid 토픽을 연결하거나 rosbag에 기록해 프레임별 흔들림을 확인합니다.

## 출발 게이트 P0
- 카메라 암부 초기 이미지/신호 게이트 기준값이 확인된 뒤에만 점등을 시작합니다.
- `wait_camera_ready.py`는 Bool 토픽을 지속 구독하여 3회 연속 true를 확인합니다.
- Depth/LiDAR 센서 신선도는 실제 움직임을 위한 별도 필수 조건입니다. 카메라 초기 준비와 혼동하지 않습니다.
- 카메라 출발 신호 검증 없이 차량을 출발시키지 않습니다.

## 검증 담당자 P0 체크
1. 신호등 준비 -> 빨간 점등 -> 5등 동시 소등 -> 카메라 LIGHTS_OUT -> 어댑터 출력 -> 실제 odom >5m.
2. RGB 인식 좌우 경계/BEV 자유공간/생성 경로의 실제 영상 겹침이 일치하는지 비교.
3. 센서 1개만 순간 오차 발생했을 때 조향이 역전하지 않는지, 두 센서가 함께 실제 코너로 변할 때 따라가는지.
4. 직선에서 10m당 좌우 조향 부호 전환, RMS 중앙오차, 경계벽 최소거리, BRAKE/STOP 이유.
5. 첫 코너에서 시간별 목표 경로/조향각/실제 yaw-rate/측정 노면 높이 및 이탈.
6. 5m/s의 반복 완주가 실제 입증되기 전 8/10m/s 단계 및 experimental RL을 활성화하지 않습니다.
