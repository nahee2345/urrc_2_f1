# 제출 조건 확인

1. 팀 코드·ROS 패키지·차량 모델·센서 설정·Launch·파라미터는 모두 이 폴더에 포함됩니다. 외부 메시/텍스처가 없는 기본 기하 모델입니다.
2. team_01 폴더 하나를 새 workspace의 src/team/team_01로 복사해 표준 ROS 환경만으로 빌드했습니다. 공통 의존성은 package.xml과 README.md에 선언합니다.
3. entry_id=team_01, ROS 패키지=team_01_race, 알고리즘=competition.launch.py, 모델=src/team_01_race/models/team_01_car/model.sdf입니다. base_link는 실제 동적 차체 링크입니다.
4. 팀 노드·제어·센서·프레임은 team_01 이름으로 구분됩니다. 팀 토픽은 /team_01/...이고 운영자 출발 신호는 /race/start/team_01입니다.
5. 실제 차량 RGB-D 카메라로 5개 빨간등 전체 소등을 인식한 뒤 출발했습니다. 출발 Bool만 True인 경우와 4개 점등/소등은 거부했습니다. 실제 RGB/Depth/LiDAR 데이터 및 SENSOR_DATA/BEST_EFFORT QoS 수신을 확인했습니다.
6. 알고리즘 실행 후 운영자 스폰 전에는 차량 0대, 운영자 스폰 후에는 차량 1대였습니다. competition.launch.py 및 제어 노드에서는 월드/차량을 생성하지 않습니다. 사용자가 명시적으로 호출하는 숫자1/2/3 연습 모드는 별도의 practice.py이며 대회 진입점과 분리됩니다.
7. 대회 알고리즘은 개인 PC 절대경로·다른 팀 코드·운영자 스크립트·개인 맵 소스를 참조하지 않습니다. 연습용1번만 공통 맵과 사용자가 지정한 출발 위치를 사용하며 알고리즘에는 전달하지 않습니다. 운영자의 실제 Gazebo 월드/차량 및 표준 ROS/Gazebo 설치 환경에 연결합니다.

전체 기본 회귀 381개와 ROS 연결 검사를 수행했습니다. 운영자 정적 검사는 오류 0개이나, 복수 링크·회전 형상의 수동 검토 경고가 남습니다. 제출 구조/센서/출발 검증은 모든 맵의 고속 완주나 운영자의 최종 규격 승인을 보장하지 않습니다.
