# TEAM 11 통합 대회용 주행 로직 — 실행 및 검증

이 문서는 현재 `src/team_11/team11_race/`의 **대회 ROS 2 실행 로직**을 기준으로 합니다.
이전 `three_lane/plugin/Team11ThreeLane.cc`는 연습용 독립 Gazebo 플러그인이고
정식 대회 `race.launch.py`에서는 직접 실행하지 않습니다.
연습용으로만 구현했던 전방 추월·코너 중앙 합류·후방 방어 정책을
`team11_race/strategy.py`에 센서 기반 Python 로직으로 이식했습니다.

## 통합 우선순위

1. **공식 출발 게이트 FALSE/위치 미수신/도로 이탈/명령 미수신**: 속도 0, 정지
2. **전방 추월**: 자기 전방 LiDAR로 확인한 같은 경로 앞차와 충돌시간(TTC) ≤3초,
   상대 접근속도 ≥2m/s, 근접 궤적 및 인접 경로가 안전할 때
3. **코너 중앙 경로**: 전방 코너 곡률 ≥0.030/m이면 1·3번 경로에서 2번 경로로
   안전하게 5차 다항 변경. 추월과 겹치면 추월 우선
4. **후방 방어**: 후방 LiDAR 실제 반복 관측, 뒤차 접근속도 ≥2m/s,
   TTC ≤5초, 코너·추월·변경 중이 아닐 때 안전한 인접 경로 변경.
   급격한 횡이동 반복 감지 시 S자 방어 방향 선택 검토
5. **기존 경로 유지**: 안전한 경로가 없다면 앞차 속도에 맞춰 감속

차선 변경은 인접 1개씩, 최소 18m에 걸쳐 진행합니다.
완료 후 이전 경로로 강제 복귀하지 않습니다.
최대 조향 약 ±29.8°, 최대 요레이트 1.2rad/s,
가속 +2m/s², 감속 -4m/s², 일반 직선 최대 15m/s,
코너·조향 제약 시 약 5~7m/s 또는 더 낮은 속도입니다.

## 신호등: 1~11번 그리드

- 카메라 FOV를 넓히고 해상도·빨간색 검색 범위를 조정했습니다.
- 저장된 6개 맵의 1~11번 그리드에 대해 시작점 기준 대략적인 카메라
  수평·수직 시야 범위 검사를 제공합니다.
- **카메라 빨간색 점등 후 완전 소등**이 1순위 출발 근거입니다.
- 카메라 인식 불가 시 **공식 출발 허가 TRUE 수신 후**
  자기 전·후방 LiDAR로 옆 차량의 실제 전진을 확인하면 출발합니다.
- 단독 예선처럼 옆 차가 없는 경우 공식 허가 0.75초 후 출발합니다.
  다중 차량에서 옆 차 움직임을 검출하지 못하면 공식 허가 2초 후 출발합니다.
- 공식 허가 FALSE 상태에서는 카메라가 꺼지거나 옆 차량이 이동해도
  TEAM 11은 출발하지 않습니다.
- 이것은 그리드별 광학 시야 근사 검증입니다.
  **11개 그리드의 실제 Gazebo RGB 렌더링이 성공했다고 주장하지 않습니다.**

## 대회용 주변 차량 인식

외부 팀의 모델 위치를 몰래 읽거나 대회 계측 토픽을 사용하지 않습니다.
TEAM 11 자체 전방/후방 LiDAR에서 공간상 연속된 작은 반사 군집을
추적하고, 자기 차량 위치를 이용해 상대 속도를 추정합니다.
벽·연석이 차량으로 오인될 수 있으므로 경로 인접성, 관측 횟수,
충돌 예상 궤적을 추가로 검사합니다.
제한된 시야와 Gazebo 레이저 모델로 **모든 추월·방어 성공을 보장하지는 못합니다.**

## urrc_2_f1 안에서 오프라인 검증

```bash
cd ~/urrc_2_f1
git switch main
git pull --ff-only origin main

bash src/team_11/test_team11_unified.sh
```

ROS 2 Jazzy 빌드까지 확인할 때:

```bash
cd ~/urrc_2_f1
bash src/team_11/test_team11_unified.sh --ros
```

이는 **경로·신호 판단·센서 추적·전술 우선순위·패키지 빌드 검증**이며
Gazebo의 실제 차량 주행이나 공식 2랩 완주를 대신하지 못합니다.
`urrc_2_f1` 저장소만에는 원본 대회 Gazebo 월드 SDF가 포함되어 있지 않습니다.
전체 실주행은 대회장이 생성한 월드/스폰과 연결해야 합니다.
연습용 `three_lane/run_demo.py` 실행은 기존 C++ 독립 데모를 검증하며,
새 ROS 2 제어기 전체를 검증하는 방법과 다릅니다.
